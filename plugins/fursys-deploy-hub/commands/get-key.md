description: 사내 배포 키 발급을 신청한다 (IT본부가 발급 → /set-key 로 등록). 오직 /get-key 슬래시 커맨드로만 동작한다.
---

사용자가 `/get-key` 를 실행했다. 사내 배포 키 **발급 신청**을 돕는다.

**중요(보안):** 배포 키는 클라이언트가 직접 만들 수 없다. IT본부(AI추진팀)가 board에서 발급한다(사내 GitHub 가입 신청과 같은 구조). 이 커맨드는 키를 만들지 않고 **발급 신청을 돕고, 받은 키를 `/set-key` 로 등록하도록 안내**한다. 키 값은 절대 출력·파일 기록하지 않는다.

### 1) 이미 키가 있는지 먼저 확인
`deploy` 스킬 번들 스크립트로 현재 키 상태를 확인한다. **이 스크립트는 플러그인 번들이라 현재 폴더에 없는 게 정상**이다(cwd에서 찾거나 위치를 되묻지 말 것).
```bash
"$CLAUDE_PLUGIN_ROOT/skills/deploy/scripts/key-status.sh"
```
(`$CLAUDE_PLUGIN_ROOT` 가 비면: `KS="$(find "$HOME/.claude/plugins" -path '*/fursys-deploy-hub/skills/deploy/scripts/key-status.sh' 2>/dev/null | head -1)"; "$KS"`)
- `KEY_FILE`/`KEY_ENV`/`KEY_BOTH` (키 있음) → "이미 배포 키가 등록돼 있어요. 새로 발급받지 않아도 돼요 — 바로 `/deploy-check`·`/deploy` 를 쓰시면 됩니다." 하고 종료(앞부분/값 출력 불필요).
- `NO_KEY` → 2)로 진행.

### 2) 신청 정보 모으기
이름·소속(팀/브랜드)·회사 이메일이 필요하다. 대화에서 이미 알 수 있으면 확인만 받는다(다시 묻지 않는다).

### 3) 신청 메시지 만들기 (형식 고정 — 토씨 그대로)
```
[사내 배포 키 발급 신청]
- 이름: <이름>
- 소속: <소속>
- 이메일: <이메일>
사내 배포(fursys-deploy-hub) 개인 배포 키 발급 부탁드립니다.
```

### 4) 발송 (Slack 도구 있으면 자동 · 없으면 복붙 가이드)
- **Slack 메시지 도구가 있으면** → 위 메시지를 **미리보기로 보여주고 확인받은 뒤** `#ask-ai추진팀` 채널로 보낸다(회사 채널에 글을 올리는 외부 행동이므로 **반드시 확인 후 발송**). 성공: "발급 신청을 보냈어요. IT본부가 확인 후 키를 전달해 드려요."
  - 발송 실패(권한 등)·도구 없음 → 아래 수동 가이드로 폴백.
- **Slack 도구가 없으면(대부분)** → 수동 가이드:
  > "배포 키는 Slack으로 신청해요. 아래 메시지를 복사해서 `#ask-ai추진팀` 채널에 올려주세요. IT본부가 확인 후 키를 전달해 드려요.
  >
  > (위 신청 메시지 블록)"

### 5) 신청 후 안내
> "키를 받으면 `/set-key` 로 등록하면 끝이에요. 그다음 `/deploy-check`(배포 전 검토)와 `/deploy`(배포)가 바로 동작해요."
- 발급은 사람 승인이 필요한 절차라 지금 바로 끝낼 수 없다 — 여기서 멈춘다.

모든 응답은 한글, 비개발자가 이해하기 쉽게. **오직 `/get-key` 명시 호출에서만 동작**하고, "키 발급해줘" 같은 자연어만으로는 시작하지 않는다.
