description: 사내 서버에 앱을 처음으로 올린다 (이후 수정은 git push 자동 재배포).
---

사용자가 `/deploy` 를 실행했다. 사내 서버에 앱을 처음 올리는 작업을 시작한다.

**`deploy` 스킬을 사용해** 처리하라. 스킬의 절차를 그대로 따른다:
- 사용자에게 묻는 건 **딱 두 가지**(① 어느 브랜드/공간, ② 접속 주소 앞부분). 그 외는 자동 처리.
- 키 확보 → 전송 대상 가드 → GitHub 올리기 → 로컬 검토 게이트 확인 → `scripts/deploy.sh` 로 생성·폴링 → 실패 시 `scripts/logs.sh` 로 원인 해설.
- 배포 **가능 여부 검토** 요청("배포해도 되는지/다시 검토")은 이 스킬이 아니라 `deploy-check` 스킬(배포 전 검토)로 안내한다.

**배포 대상 서버 (v4.6 — 운영 2호기 표준):**
- **배포 실행 시(스킬 ⑥) `scripts/deploy.sh` 에 `--server coolify-oper-web-2` 를 항상 붙인다.** 신규 앱은 운영 2호기에 올라간다.
- **접속 주소 안내는 `{앞부분}.app2.hub.fursys.com` 으로 한다.** 예: 앞부분 `event` → `event.app2.hub.fursys.com`. 확정 주소를 사용자에게 그대로 보여주고 확인받는다.
- 이미 올라가 있는 **기존 앱은 예전 주소(`~.group.hub.fursys.com` 등)를 그대로 유지**한다 — 재등록해도 주소·서버가 바뀌지 않는다.
- deploy.sh 가 `SERVER_UNKNOWN` 을 주면 "배포 서버를 찾지 못했어요. IT본부에 문의해 주세요." 라고 안내하고 멈춘다.

모든 응답은 한글, 비개발자가 이해할 수 있게 쉽게.
