---
description: 사내 서버에 앱을 처음으로 올린다 — 여유 있는 서버에 자동 배치 (이후 수정은 git push 자동 재배포).
---

사용자가 `/deploy` 를 실행했다. 사내 서버에 앱을 처음 올리는 작업을 시작한다. **서버는 사람이 고르지 않는다 — 시스템이 두 서버의 최근 부하(CPU·메모리 10분 평균)를 보고 여유 있는 쪽에 자동 배치한다** (v4.7 표준 — 구 `/deploy2`·`/deploy-dev` 는 이 표준화로 제거됨).

**`deploy` 스킬을 사용해** 처리하라. 스킬의 절차를 그대로 따른다:
- 사용자에게 묻는 건 **딱 두 가지**(① 어느 브랜드/공간, ② 접속 주소 앞부분). 그 외는 자동 처리.
- 키 확보 → 전송 대상 가드 → GitHub 올리기 → 로컬 검토 게이트 확인 → `scripts/deploy.sh` 로 생성·폴링 → 실패 시 `scripts/logs.sh` 로 원인 해설.
- 배포 **가능 여부 검토** 요청("배포해도 되는지/다시 검토")은 이 스킬이 아니라 `deploy-check` 스킬(배포 전 검토)로 안내한다.

**자동 배치 (v4.7 표준):**
- **배포 실행 시(스킬 ⑥) `scripts/deploy.sh` 에 `--server auto` 를 항상 붙인다.** 중앙 배포 시스템이 두 서버의 최근 CPU·메모리 사용률(10분 이동평균)을 비교해 여유 있는 서버를 고른다. **사용률을 읽을 수 없으면 번호가 높은 서버(현재 2호기)로 자동 폴백**한다 — 어느 쪽이든 배포는 진행된다.
- **접속 주소는 배포가 끝나야 확정된다** — 어느 서버로 갔는지에 따라 `{앞부분}.app1.hub.fursys.com`(1호기) 또는 `{앞부분}.app2.hub.fursys.com`(2호기)이 된다. 주소 앞부분을 확인받을 때 이렇게 안내한다: "서버는 시스템이 여유 있는 쪽으로 자동으로 골라요. 최종 주소는 `{앞부분}.app1.hub.fursys.com` 또는 `{앞부분}.app2.hub.fursys.com` 중 하나로 정해지고, 끝나면 알려드릴게요."
- **배포 결과로 "왜 그 서버인지"까지 안내한다** — deploy.sh 가 `CREATED`/`REDEPLOYED` 줄 다음에 출력하는 **응답 JSON 의 `placement`·`placement_reason`** 을 읽는다:
  - `placement:"auto-metrics"` → 실제 부하를 비교해 고른 것. `placement_reason` 의 수치를 그대로 인용해 안내한다: "두 서버 부하를 비교해서 여유 있는 **○호기**에 올렸어요 (예: coolify-oper-web-1: cpu 12%/mem 40% vs coolify-oper-web-2: cpu 78%/mem 65%)."
  - `placement:"auto-fallback"` → 지표를 읽지 못해 규칙대로 보낸 것. 솔직하게 안내한다: "부하 지표를 읽을 수 없어서, 정해진 규칙대로 **2호기(번호 높은 서버)** 에 올렸어요."
  - (참고) 운영 확인용: 배포 없이 브라우저로 `https://deploy-proxy.hub.fursys.com/placement` 를 열면 "지금 배포하면 어디로, 왜(mode=metrics/fallback)"를 미리 볼 수 있다.
- **이미 올라가 있는 기존 앱은 예전 주소·서버를 그대로 유지한다** — 재등록해도 바뀌지 않는다(주소 보존).
- deploy.sh 가 `SERVER_UNKNOWN` 을 주면(중앙 시스템이 자동 배치를 지원하지 않는 구버전) "자동 배치가 아직 준비 안 됐어요. IT본부에 중앙 시스템 업데이트를 문의해 주세요." 라고 안내하고 멈춘다.

**사내 로그인 보호 (기본 적용):**
- 사내 서버에 올라간 앱은 **회사 계정으로 로그인해야 열린다**(중앙 배포 시스템이 배포할 때 자동으로 걸어 준다 — 사용자가 할 일 없음).
- 그래서 배포 후 첫 접속에 **로그인 화면이 뜨는 건 정상**이다. 오류로 설명하지 말고 "회사 계정으로 들어가시면 돼요"로 안내한다.
- 로그인 없이 열려야 하는 앱은 **IT본부 AI추진팀에 사유와 함께 신청**하면 풀어준다(스킬이 임의로 풀 수 없다).
- 보호 설정을 못 붙이면 시스템이 **배포를 멈춘다**(`LABEL_FAILED`) — 보호 없이 올리지 않기 위한 안전장치다. 이땐 앱이 실행되지 않았으니 다시 `/deploy` 하면 된다.

모든 응답은 한글, 비개발자가 이해할 수 있게 쉽게.
